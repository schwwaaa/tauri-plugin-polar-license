# Front end: API, drop-in UI, permissions

## Permissions (required)

Tauri v2 only lets the front end call plugin commands you grant in a
capability:

```jsonc
// src-tauri/capabilities/default.json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "windows": ["main"],            // every window that shows the gate or panel
  "permissions": ["core:default", "polar-license:default"]
}
```

`polar-license:default` allows `status`, `activate`, `release` and
`launch_check`. To grant them individually, use `polar-license:allow-status`
and so on (generated reference: `permissions/autogenerated/reference.md`).

## Option A: the drop-in UI

Two components, plain JS and CSS, no framework, no build step.

- **Gate:** a full-window overlay with a key field, Activate, and an optional Quit. Shown until the app is licensed.
- **Panel:** status, this computer, masked key, activation date, server, last check, and **Release this machine** (two clicks within 4 seconds, to guard against stray clicks).

### Install

Copy `ui/polar-license.js` and `ui/polar-license.css` into your front end
(or import them from the npm package's `ui/` folder).

```html
<link rel="stylesheet" href="polar-license.css">
<script src="polar-license.js"></script>
```

It works under a strict CSP (`script-src 'self'`): there are no inline
scripts or styles, and everything is built with `textContent`.

### Mount

```js
PolarLicenseUI.mount({
  appName: 'Voxel Feedback Volume',  // used in the gate title and panel header
  onLicensed: (status) => startUi(), // licensed at launch, or right after activation
  onReleased: () => quitApp(),       // after "Release this machine" (1.2 s after success)
  onQuit: () => quitApp(),           // optional: shows a Quit button on the gate
  invoke,                            // optional: defaults to window.__TAURI__.core.invoke
  text: { gateTitle: '…' },          // optional: override any wording (keys below)
});

document.querySelector('#gear').addEventListener('click', () => PolarLicenseUI.openPanel());
```

`mount()` returns a promise for the `LicenseStatus`.

### Wording overrides (`text`)

`gateEyebrow`, `gateTitle`, `gateBody`, `activate`, `activating`,
`contacting`, `quit`, `panelTitle`, `release`, `releaseConfirm`,
`releasing`, `released`, `releaseHelp`, `close`.

Error messages come from the plugin (Rust) and are customer-ready. To show
your own wording, use the error's `kind` with Option B.

### Theming

Override CSS variables on `:root` (or any ancestor):

| Variable | Default | Used for |
|---|---|---|
| `--pl-font`, `--pl-mono` | system UI / monospace | text, key field |
| `--pl-backdrop` | `rgba(4,6,11,.82)` | overlay behind dialogs |
| `--pl-surface`, `--pl-surface-2` | `#0f1520`, `#141c28` | dialog, inputs and buttons |
| `--pl-border`, `--pl-border-strong` | `#29364a`, `#3c4b63` | outlines |
| `--pl-text`, `--pl-muted` | `#eef5fb`, `#98a8bc` | text |
| `--pl-accent`, `--pl-accent-text` | `#67d8ff`, `#04121a` | primary button, focus |
| `--pl-eyebrow` | `#a8ff8b` | small heading above titles |
| `--pl-danger`, `--pl-ok` | `#ff8d9b`, `#86f1ae` | errors, success |
| `--pl-radius`, `--pl-control-radius` | `14px`, `9px` | corners |
| `--pl-z` | `10000` | stacking order |

All classes are prefixed `pl-`.

## Option B: your own UI with the typed API

```bash
npm install tauri-plugin-polar-license-api
```

```ts
import {
  getStatus, activate, release, getLaunchCheck, waitForLaunchCheck,
  type LicenseStatus, type LaunchCheck, type LicenseError,
} from 'tauri-plugin-polar-license-api';
```

| Function | Returns | Notes |
|---|---|---|
| `getStatus()` | `LicenseStatus` | Local file only; instant, works offline |
| `activate(key)` | `LicenseStatus` | Runs your `on_licensed` before resolving. Rejects with `LicenseError`. |
| `release()` | `void` | Frees this computer's slot and deletes the local license. Rejects with `LicenseError`. |
| `getLaunchCheck()` | `LaunchCheck` | `state`: `pending`, `notLicensed`, `confirmed`, `deactivated` or `offline` |
| `waitForLaunchCheck(timeoutMs?, intervalMs?)` | `LaunchCheck` | Polls until the state isn't `pending` |

### Handling errors by kind

```ts
try {
  await activate(input.value);
} catch (e) {
  const err = e as LicenseError;
  switch (err.kind) {
    case 'inUseElsewhere': showMoveHelp(); break;   // explain "Release this machine"
    case 'deactivated':    showContactSupport(); break;
    case 'network':        showRetry(); break;
    default:               showMessage(err.message); // always customer-ready
  }
}
```

| `kind` | Meaning |
|---|---|
| `notConfigured` | Polar IDs missing in this build |
| `emptyKey` | Nothing was entered |
| `notRecognized` | Unknown key (typo, or a key from the other environment) |
| `wrongProduct` | A real key, but for another of your products |
| `inUseElsewhere` | All activation slots are used by other computers |
| `deactivated` | Key revoked, disabled or expired |
| `network` | No connection, or a timeout |
| `storage` | Couldn't write the license file |
| `nothingToRelease` | Release requested, but this computer isn't activated |
| `unexpected` | Anything else (details in the developer log) |
