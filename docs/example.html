Licensed beforethe first frame.

A complete Tauri v2 app wired to tauri-plugin-polar-license. It’s a GPU voxel renderer that doesn’t create its window, or touch the GPU, until the license key is valid. Clone it, add your Polar IDs, and try every licensing case with a real key before adding the plugin to your own app.

Five files do the licensing

Everything else in the repo is the demo app. These are the parts to copy into yours.

  • polar_config.rs

    Builds the plugin: your Polar IDs, the sandbox or production switch, the optional Worker and support contact, and on_licensed, which starts the renderer.

  • main.rs

    Registers the plugin with one line, and defines start_renderer(), which only the plugin calls.

  • capabilities/default.json

    Lets the controls window use the plugin’s commands with polar-license:default.

  • app.js

    Mounts the activation screen and adds a License button that opens the license panel.

  • build.rs

    Reads your settings from a local polar.env file, so your IDs never land in the repository.

Set it up

You need Rust, Node.js 18 or newer, the Tauri v2 prerequisites, and a Polar product with a License Keys benefit.

  1. Install the JavaScript dependencies

    In a terminal, in the repository’s folder:

    npm install

  2. Create your settings file

    Copy the template. The copy is git-ignored, so it stays on your machine.

    cp src-tauri/polar.env.example src-tauri/polar.env

  3. Fill in your Polar IDs

    Open src-tauri/polar.env in an editor. You only need the pair for the Polar you’ll test against. Where to find each ID.

    # src-tauri/polar.env
POLAR_PRODUCTION_ORGANIZATION_ID=your-org-id
POLAR_PRODUCTION_BENEFIT_ID=your-benefit-id
POLAR_SANDBOX_ORGANIZATION_ID=your-sandbox-org-id
POLAR_SANDBOX_BENEFIT_ID=your-sandbox-benefit-id

# optional
POLAR_RECLAIM_URL=https://polar-license.yourname.workers.dev
POLAR_SUPPORT_CONTACT=support@yourapp.com

Run it

Debug builds talk to the Polar sandbox unless you ask for production.

npm run dev:metalPolar sandbox, debug build, macOS
npm run dev:metal:productionPolar production, debug build, macOS
npm run dev:vulkanPolar sandbox, debug build. Also dev:dx12 and dev:gl
npm run buildPolar production, release build

A sandbox build’s activation screen says “Test build — using the Polar sandbox.” Debug builds also print a [polar-license] line in the terminal for every licensing event.

Test every case with one key

Get a sandbox key with the test card 4242 4242 4242 4242, or a production key from a free product or a 100% discount code.

  1. Activate

    Paste the key and click Activate. The activation screen closes and the renderer window opens. The only step that needs the internet.

  2. Relaunch

    Quit and run the app again. The renderer opens immediately, with no activation screen.

  3. Relaunch offline

    Turn off Wi-Fi and run it again. The renderer still opens. The license panel says the license wasn’t checked this time.

  4. Release this machine

    Open the License panel, click Release this machine, then click again to confirm. The app quits, and Polar shows no activations for the key.

  5. Activate again

    Run the app and paste the key. It activates, using the slot you just freed.

  6. Disable the key in Polar

    Run the app twice. The first run still works and the panel says the license was deactivated. The second shows the activation screen.

  7. Re-enable it

    Enable the key in Polar and paste it again. It activates.

Don’t revoke a key you want to keep testing with. In Polar a revoke is permanent: re-enabling it afterwards changes nothing. More in the caveats.
